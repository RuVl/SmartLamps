# 1. Arduino, а не ESP8266 RTOS SDK

## Контекст

Прошивке нужны: веб-панель настроек, база настроек, аппаратный вывод на ленту, OTA,
MQTT. Для ESP8266 есть три пути: Arduino-ядро, `ESP8266_RTOS_SDK` (FreeRTOS, API «в
стиле IDF») и NonOS SDK.

## Решение

Arduino.

## Причины

Вся экосистема, из которой собран проект, — Arduino-библиотеки: GyverLibs Settings и
GyverDB (панель и база), EncButton (кнопка), NeoPixelBus (I2S DMA на ленту), FastLED
(цветовая математика), ESPAsyncWebServer и AsyncMqttClient. Под RTOS SDK ничего из
этого не собирается: панель, базу, OTA и MQTT пришлось бы писать заново ради FreeRTOS,
который лампе с одним кооперативным циклом не нужен.

Цена Arduino известна и учтена в коде: колбэки async-сервера выполняются в
sys-контексте SDK с маленьким стеком (`docs/hardware.md`, «Панель и sys-контекст»),
тяжёлая работа из них выносится в `loop()`.

## Следствия

**Arduino API не должен просачиваться в ядро.** `core/` и `effects/` не используют
`String`, `millis()`, `Serial` и прочий Arduino — только `hal/`. Это и делает возможными
тесты и симулятор на хосте, и это же граница, по которой прошивку можно было бы
перенести на другой фреймворк: переезжает HAL, эффекты и ядро остаются нетронутыми.
