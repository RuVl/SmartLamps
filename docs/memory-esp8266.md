# Память ESP8266 (лампа B)

У Wemos D1 mini 80 КБ DRAM без MMU. Цифра «RAM» в выводе компоновщика — только
статика; панель, WiFi и MQTT берут остальное во время работы, и прошивка, которая
нормально линкуется, может быть в одной загрузке страницы от падения. Здесь: что
именно занимает память, откуда взяты цифры, как считается бюджет при сборке
(`tools/memory_budget.py`) и что показал стенд.

Три сорта чисел, они так и помечены:

- **точно** — из ELF или из флагов сборки;
- **из исходников** — формула из кода библиотеки, не догадка;
- **измерено** — на плате, с датой и прошивкой. После изменений сетевого стека,
  раскладки панели или размера журнала — перемерить.

пакеты и WiFi отваливается — это порог `FAIL_FREE` в скрипте.

### Как панель строит страницу

`SettingsBase::_sendBuild` собирает BSON в один `Packet` (`reserve(1024 + 128)`),
после каждого виджета проверяет длину и при > 1 024 Б отдаёт кусок в `ws.binary()`.
Всё это синхронно внутри WS-колбэка, то есть на системном стеке. Следствия:

- каждый кусок `ws.binary()` = `malloc(len + 1)` копия в очереди клиента; очередь —
  `WS_MAX_QUEUED_MESSAGES` = **8** на ESP8266, лишнее **молча выбрасывается**
  (`ERROR: Too many messages queued`). Страница длиннее 8 КБ приходит обрезанной.
  Это не краш, но «панель пустая» — отсюда;
- пока идёт build, ack не обрабатываются: в TCP уходит только первый ~1 072 Б,
  остальные куски висят в очереди до конца сборки;
- виджет `Log` — это копия всего буфера журнала в странице. На `dev` было три
  копии полного журнала (WiFi, MQTT, Система): 3 120 Б из ~4 800 Б страницы. Теперь
  полный (1 024 Б) только в «Система», а WiFi и MQTT показывают свои короткие
  журналы по 320 Б (`kTopicLogBytes`, строки с префиксом `WiFi:`/`OTA:` и `MQTT:`):
  +640 Б статики, +~670 Б в странице и в каждом `pushLog()`.

Пик одной сборки страницы (модель): буфер пакета ~2,2 КБ + очередь копий (страница −
1 072) + pbuf 1 072 + служебное ≈ **6,7 КБ** при странице 3,1 КБ (один `Log`);
на `dev` с тремя `Log` было ≈ 9,9 КБ.

`pushLog()` раз в секунду при грязном журнале: `InlineUpdater` без reserve, рост по
8 Б через `realloc`. На `dev` — `log().toString()` 1 024 Б + пакет ~3 300 Б (три копии
журнала) + WS-копия 3 300 + pbuf: **~9–10 КБ** пика. Теперь — перегрузка
`update(id, Logger&)` пишет журнал прямо в пакет, копий нет: пакет ~1 250 Б, пик ~3,6 КБ.

### Размер страницы по эффектам (модель, журнал полон, один `Log`)

Шапка + WiFi + MQTT + Система без журнала ≈ 1 470 Б (откалибровано по измеренной
странице 4 790 Б с тремя журналами и эффектом «Тест»). Эффект добавляет 48 Б на
виджет + метку + строку опций `Select`.

| Эффект | Параметров | Страница | Кусков |
|---|---|---|---|
| Шум 3D | 3 (Select, 92 Б опций) | 3 116 | 4 |
| Огонь | 4 | ~3 100 | 4 |
| Радуга | 3 (Select) | ~3 090 | 4 |
| Тест | 1 (Select, 130 Б) | ~3 050 | 3–4 |
| остальные | 2–3 | 2 980–3 040 | 3 |

Разброс между эффектами — ~140 Б из 3 КБ. **Размер страницы не объясняет «падает на
некоторых эффектах»** — см. стенд ниже.

## Бюджет при сборке — `tools/memory_budget.py`

Post-build для `[env:d1_mini]` и всего, что его наследует. Читает `_heap_start` из
ELF, число и размер `b.Log(`/`kLogBytes` и параметры эффектов из исходников, флаги
матрицы и каденции из `CPPDEFINES`, и считает:

```
free_idle  = (0x3FFFC000 − _heap_start) − IDLE_TAKEN                 ; точно − измерено
transient  = max(HTTP_BURST, build_peak + push_peak) + MQTT_JSON       ; модель
free_worst = free_idle − transient
```

- `build_peak` = (1 024 + 128 + kLogBytes) + страница + 1 072 + 300;
- `push_peak` = 2 × пакет pushLog + 1 072;
- `HTTP_BURST` 6 КБ (браузер тянет страницу до открытия WS — не пересекается со
  сборкой, поэтому берётся большее из двух), `MQTT_JSON` 2,4 КБ (пул ArduinoJson +
  строка discovery/state, которые `publishState()` строит в `loop()` после каждого
  движения слайдера).

Две проверки:

1. **точная**: страница ≤ 8 кусков по 1 024 Б, иначе панель обрезается → сборка
   отклоняется;
2. **модельная**: `free_worst` < 4 КБ → отклоняется, < 8 КБ → предупреждение (запас
   на фрагментацию: pushLog нужен один непрерывный блок).

Вывод на текущей ветке:

```
heap at boot             39992  exact
idle, everything up    - 19600  measured 2026-09-19
= free at idle           20392
page build peak        -  6664  model   page 3116 B (Шум 3D, 1 Log x 1024) = 4 chunks
pushLog peak           -  3568  model
MQTT JSON              -  2400  model
= worst-case free         7760  model   (fail < 4096, warn < 8192)
```

На `dev` (три `Log`, `toString()` в pushLog) та же формула даёт ≈ −1 КБ: страница
4,9 КБ, сборка 9,9 КБ, pushLog 7,7 КБ.

### Что перемерить после прошивки `d1_mini_mem`

Сборка `pio run -e d1_mini_mem` печатает в UART раз в секунду:

```
mem: free=… blk=… frag=… cont=… minfree=… minblk=… mincont=… sys=… fx=… foc=… mqtt=… up=…
```

`free/blk/frag` — `ESP.getHeapStats()`, `cont` — свободный стек `loop()`, `min*` —
минимумы с загрузки, `sys` — глубина системного стека, до которой доходил колбэк
сборки панели (`a1` в `build()`), `foc` — панель в фокусе. Дополнительно
`-DDEBUG_ESP_OOM` печатает `:oom(size)@file:line` на каждый неудавшийся `malloc`,
`-DUMM_POISON_CHECK_LITE` ловит запись за границу блока при `free`/`realloc` и
называет файл и строку. При старте всегда печатается `reset: <причина>`.

Константы скрипта, которые берутся из этой телеметрии:

1. `IDLE_TAKEN` = 39 472 − `free` в покое с открытой панелью и брокером;
2. `TRANSIENT_PEAK_MEASURED` = `free` в покое − `minfree` после прогона матрицы
   (`tools/stress/matrix.py`: `load`, `sliders`, `fastfx`, `power`, `twin`,
   `mqttburst`, `both`, `logspam`) — заменяет модельную сумму;
3. `mincont` и `sys` — чтобы знать запас обоих стеков; `sys` > 4 КБ — тревога.

## Стенд, 2026-09-19

Скрипты — в `tools/stress/`:

- `serial_capture.py /dev/ttyUSB0 out/run` — захват UART только на чтение
  (`.log`, `.csv` из строк `mem:`, `.events` с исключениями и сбросами). Открытие порта
  всё равно дёргает RST один раз — запускать до теста и не перезапускать;
- `sets_ws.py <ip> [--pass …] load|set|click|spam|mem …` — панель по WS-протоколу
  Settings без браузера (`mem` — загрузить страницу и вынуть метку «Память»);
- `matrix.py <case>…` — матрица: `load`, `sliders`, `fastsliders`, `fastfx`, `power`,
  `twin`, `mqttburst`, `both`, `logspam`, `spamlong`, `soak`; после каждого шага пишет
  куча/блок/стек из метки панели в `OUT.csv`. Переменные `LAMP`, `NAME`, `BROKER`
  (по умолчанию — домашний стенд автора: 192.168.31.220 / 192.168.31.21),
  `PASS`, `NOMQTT=1`;
- `mqtt_only.py [кругов]` — та же нагрузка через MQTT без панели.

Зависимости: `uv run --with websockets --with paho-mqtt`, pyserial системный.

Плата: Wemos D1 mini, `lead=1`, 3-step, кнопка активна. Прошивка `dev` (то, что было
на плате, без правок этой ветки). UART читается только на чтение; панель гоняется
скриптом по WS-протоколу Settings (без браузера), MQTT — брокер Mosquitto на ноутбуке.
Нагрузка «слайдеры» = для каждого из 12 эффектов: `set efcx` → 0,6 с → `load` → по
каждому параметру 40 `set` с шагом 250 мс (частота реального слайдера в браузере,
`sliderTout`). Полный круг — 1 200 `set`, 12 переключений, 12 загрузок страницы.

| # | Нагрузка | Результат | Куча в покое (`free` / `blk`) |
|---|---|---|---|
| A1 | панель + MQTT, полный круг | **краш** на 2-м эффекте (~120 set): `Exception (3)` в `umm_malloc_core` из приёма lwIP | 21,5 / 20,7 КБ |
| A3 | панель + MQTT, полный круг | **краш** на 2-м эффекте (~50 set): `Soft WDT` в `umm_free_core` из `SettingsBase::_send` (ответ на `set`) | 20,7 / 20,0 |
| A5 | панель + MQTT, без «Тест» | **краш** на 6-м эффекте (~560 set): сброс без дампа | 21,3 / 20,2 |
| A6 | панель + MQTT, полный круг | **краш** на 4-м эффекте (~260 set): `Exception (9)` в `free` из `mqtt::publishState` → `String::changeBuffer` | 24,3 / 23,1 |

| C1 | **только MQTT**, без панели: 2 круга = 2 424 команды, 24 переключения | **без сбоев**; `state` пришло на 96 % команд | — |

Выводы:

1. **Это не нехватка памяти.** Ни в одном прогоне свободная куча в `loop()` не
   опускалась ниже 20 КБ, наибольший блок — ниже 19 КБ. Все четыре дампа — внутри
   `umm_malloc`/`umm_free` (`Exception 3`/`9` с мусорным адресом, `Soft WDT` в обходе
   списка свободных блоков) с разными вызывающими: приём lwIP, ответ панели,
   `publishState`. Это подпись **испорченной кучи** — кто-то пишет за границу блока
   или в освобождённый.
2. **Портит путь панели.** 2 424 команды через MQTT без панели — чисто; тот же объём
   через WS — 6 крашей из 6 полных кругов, между 50 и 1 000 `set`. MQTT лишь ускоряет
   (больше выделений — раньше натыкается на порчу).
3. «На некоторых эффектах» — статистика, не свойство эффекта: крашится 2-й, 4-й,
   6-й, 11-й эффект круга; первый эффект круга не падал ни разу, а он был и «Тест»,
   и «Конфетти».
4. Реальный пользователь шлёт `set` с той же частотой (4/с при протяжке слайдера):
   краш — от 15 секунд до 4 минут непрерывной работы со слайдерами.

Кандидат по коду: очередь сообщений `AsyncWebSocketClient` в
ESPAsyncWebServer-esphome 3.3.0 — `_onAck` / `_runQueue` / `_cleanBuffers`, тот самый
use-after-free, что уже ловили на этой плате (шапка `WebUi.cpp`). Дамп D1 — прямое
попадание: `_runQueue()` из TCP-ack разыменовал мусорный указатель на сообщение в
очереди, и это до всякой нехватки памяти (23 КБ свободно). Троттлинг наших пушей от
него не спасает: ответы на `set` идут по каждому запросу клиента, `Settings::tick()`
шлёт обновления каждые 300 мс вне троттла, и каждый ack вызывает `_cleanBuffers()`.

## Стенд, 2026-09-20 — прошивка `d1_mini_mem` этой ветки

Та же плата, poison-проверка кучи включена, MQTT не настроен, панель по WS, статика
панели — четыре параллельных GET (`/`, `/script.js`, `/style.css`, `/favicon.svg`,
27,8 КБ gz из PROGMEM), как делает браузер при открытии.

| Нагрузка | Результат | free / блок, мин. за фазу |
|---|---|---|
| `sliders` + `fastsliders`: полный круг 1 200 `set` по 250 мс + 720 `set` по 50 мс | **без сбоев** | 21 032 / 16 296 |
| `static` × 10: страница открыта 10 раз подряд, ~0,25 с каждая | **без сбоев** | 19 224 / 15 200 |
| `browser`: 3 круга «статика × 3 → слайдеры 4 эффектов → статика × 3» + перезагрузка страницы в фоне каждые 20 с, затем ещё полный круг `sliders` | **без сбоев**, 24 мин | 20 016 / 14 840 |
| 4 HTTP-соединения, которые клиент **не читает и не закрывает** (ошибка в первой версии скрипта, 15 с) | без сбоев, но куча **10 704 / 7 136** на всё время висения; при повторе — 7 224 / 4 696 | — |

Дополнительно: `frag` ≤ 26, sys-стек в колбэке панели 1 008 Б, `cont` ≥ 2 160,
`:oom` и poison-срабатываний нет. За 24 минуты два «цикл стоял» (180 мс — запись
GyverDB в LittleFS) и одиннадцать `dma: gap` 100–195 мс — все в момент отдачи статики:
AsyncWebServer наполняет чанки gz-ответа в контексте lwIP, и `loop()` на это время не
получает процессор. Открытие панели = ~0,1–0,2 с без кадра, это видно на матрице.

Выводы 2026-09-20:

1. Порча кучи, ронявшая `dev` за 50–1 000 `set`, на этой ветке не воспроизводится ни
   слайдерами, ни статикой, ни их смесью. Что именно помогло — один `Log` вместо трёх,
   `pushLog()` без `String`-копии или команды MQTT из `tick()` — стенд не разделяет;
   форк `ESPAsyncWebServer` пока не нужен.
2. Слабое место — **зависшие HTTP-соединения**: клиент, который открыл страницу и не
   читает ответ (телефон ушёл в сон на середине загрузки), держит по ~4 КБ на
   соединение, четыре таких — 7 КБ свободной кучи. Лечится таймаутом простоя на
   `AsyncWebServer` (`setIdleTimeout`/закрытие по `onDisconnect`) — отдельная задача.
3. Не проверено: протяжка яркости (`matrix.py brightness` — кейс готов) и стенд с
   подключённым брокером (`NOMQTT` снят) — лампа выключилась раньше.

Побочные находки стенда:

- `fastled/FastLED@^3.10.3` подтягивал 3.10.5, где `dim8_video` и другие функции ушли в
  `fl::` — свежий checkout `dev` не собирался. Зафиксировано `@3.10.3`.
- Брокер в Docker с `-p 1883:1883` (NAT): лампа каждые ~115 с решала, что соединение
  порвано, открывала новое, брокер писал `session taken over`, новое тут же
  закрывалось, через 5 с — переподключение. С `--network host` цикл исчез. На
  «настоящем» брокере (`scripts/mqtt-server.sh`) не воспроизводится — но если в
  журнале лампы появятся парные «отключено» раз в две минуты, смотреть на NAT/conntrack
  между лампой и брокером.
- Кнопка на плате B срабатывает сама (яркость уезжала в 1 %): пока пад не починен,
  `[env:d1_mini]` собирается с `LAMP_BUTTON_DISABLED` (заглушка в `ButtonArduino.cpp`).
