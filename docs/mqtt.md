# MQTT

Один протокол для пары ламп, Home Assistant и отладки из командной строки.

## Топики

```
lamp/<имя>/avail                  retain, online | offline  (last will)
lamp/<имя>/state                  retain, JSON — полное состояние
lamp/<имя>/cmd/on                 0 | 1
lamp/<имя>/cmd/brightness         0..100
lamp/<имя>/cmd/effect             имя эффекта
lamp/<имя>/cmd/param/<ключ>       значение параметра активного эффекта
lamp/<имя>/event/ping             исходящий маячок
lamp/<имя>/event/ack              квитанция «увидел»
homeassistant/light/<имя>/config  автообнаружение
```

`<имя>` задаётся в веб-панели, по умолчанию складывается из MAC — `lamp-a4f2`. Имя
парной лампы указывается там же отдельным полем.

## Состояние

Публикуется с `retain`, чтобы подключившийся клиент сразу знал, что происходит:

```json
{
  "on": true,
  "brightness": 60,
  "effect": "Огонь",
  "params": { "speed": 40, "cooling": 55, "spark": 120, "hue": 10 },
  "fps": 60,
  "rssi": -58
}
```

## Зачем и плоские топики, и JSON

Плоские топики удобны для управления: кнопка в Home Assistant или `mosquitto_pub` из
терминала пишут одно значение, и никто не разбирает документ целиком ради одной правки.

JSON нужен для чтения: подписчику важно получить согласованный снимок, а не собирать
его из десятка топиков, приходящих вразнобой.

## Примеры

```bash
# включить и поставить эффект
mosquitto_pub -h БРОКЕР -p 8883 --capath /etc/ssl/certs -u ПОЛЬЗОВАТЕЛЬ -P ПАРОЛЬ \
  -t 'lamp/lamp-a4f2/cmd/on' -m 1
mosquitto_pub ... -t 'lamp/lamp-a4f2/cmd/effect' -m 'Огонь'
mosquitto_pub ... -t 'lamp/lamp-a4f2/cmd/param/speed' -m 70

# посмотреть, что происходит
mosquitto_sub ... -t 'lamp/#' -v
```

## Автообнаружение в Home Assistant

При подключении к брокеру лампа публикует конфигурацию в
`homeassistant/light/<имя>/config` по схеме `default`: отдельные топики команд, одно
JSON-состояние, читаемое через шаблоны. В Home Assistant появляется светильник с
яркостью и списком эффектов, без ручной настройки.

## Индикация

Угловой пиксель (верхний левый) поверх эффекта, мягко пульсирует:

| цвет | значение |
|---|---|
| синий | режим точки доступа, WiFi не настроен или недоступен |
| янтарный | WiFi потерян |
| пурпурный | WiFi есть, брокер MQTT настроен, но не отвечает |
| белый | идёт обновление прошивки |

В норме пиксель не рисуется. Выключенная лампа всё равно показывает индикатор на
минимальной яркости — иначе не понять, почему она не отвечает.

## Маячок

Тройное касание на лампе A публикует `lamp/lamp-b/event/ping`. Лампа B переходит в
состояние уведомления и пульсирует, пока её не тронут. Касание гасит уведомление,
возвращает прежний эффект и публикует `lamp/lamp-a/event/ack` — лампа A коротко
подтверждает, что её увидели.

Маячок ничего не меняет в настройках получателя: это не команда.

## Брокер

`scripts/mqtt-server.sh` ставит Mosquitto на Debian/Ubuntu с паролем на 1883, идемпотентно
(конфиг переписывается целиком, повторный запуск ничего не дублирует), проверяет, что
брокер отвечает, и печатает, что вписать в панель лампы:

```bash
sudo scripts/mqtt-server.sh -u lamp                     # спросит пароль
sudo scripts/mqtt-server.sh -u lamp --tls mqtt.example.com   # + 8883 с сертификатом Let's Encrypt
```

## Безопасность

Целевая схема — **8883 с TLS**: в незашифрованном MQTT логин и пароль передаются
открытым текстом, а брокер смотрит в интернет. `--tls` уже поднимает такой слушатель
(certbot standalone, порт 80 должен быть доступен), но прошивка пока говорит только по
1883 — TLS в прошивке в `docs/backlog.md`. До тех пор брокер лучше держать в домашней
сети или за VPN.
